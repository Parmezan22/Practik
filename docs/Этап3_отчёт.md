# Отчёт. Этап 3 — отчётность, печать, графики, курсы валют и тестирование

Материал для переноса в пояснительную записку (оформление по ГОСТ 19.201-78 / 19.402-78).
Заключительная часть документа; продолжает `Этап1_отчёт.md` и `Этап2_отчёт.md`.

## Введение

**Цель этапа** — довести приложение до состояния готового учебного продукта:
добавить отчётность с выгрузкой в Excel и печатью, наглядные графики,
получение данных из интернета, автоматические тесты, руководство пользователя
и релизную сборку.

**Задачи этапа:**

1. Реализовать отчёт «Записи за период» с фильтрами и итогами.
2. Реализовать экспорт отчёта в книгу Excel.
3. Реализовать печать отчёта с предварительным просмотром.
4. Добавить диаграмму числа записей по дням на экран статистики.
5. Реализовать загрузку официальных курсов валют через HTTP.
6. Закрыть оставшуюся заглушку — управление пользователями.
7. Покрыть расчётную логику модульными тестами xUnit.
8. Собрать Debug и Release, провести комплексную проверку на чистой базе.
9. Подготовить руководство пользователя и настоящий отчёт.

## 2. Отчёт «Записи за период»

Отчёт строится по тем же данным, что и журнал записей, но дополнительно
содержит стоимость каждой записи. Используется существующий метод
`AppointmentRepository.GetFiltered`, в SQL которого добавлены цена основной
услуги и сумма дополнительных:

```sql
SELECT a.Id, a.PatientName, a.DoctorId, a.ServiceId, a.Date, a.Time,
       a.Status AS StatusDb, a.CreatedByUserId,
       d.FullName AS DoctorName,
       s.Name     AS ServiceName,
       s.Price    AS Price,
       IFNULL((SELECT SUM(s2.Price)
                 FROM AppointmentServices aps
                 JOIN Services s2 ON s2.Id = aps.ServiceId
                WHERE aps.AppointmentId = a.Id), 0) AS ExtraPrice
  FROM Appointments a
  JOIN Doctors  d ON d.Id = a.DoctorId
  JOIN Services s ON s.Id = a.ServiceId;
```

В модели `Appointment` добавлены свойства `Price`, `ExtraPrice`, вычисляемое
`TotalPrice = Price + ExtraPrice` и текст `TotalPriceText` с двумя знаками.

**Фильтры экрана:**

- период «с — по» (по умолчанию — с первого числа текущего месяца по сегодня);
- врач (включая «Все врачи»);
- флажок «Только завершённые»;
- кнопка «Построить»; при обратных датах границы автоматически меняются местами.

**Итоги внизу экрана:**

- количество записей, завершённых и отменённых;
- сумма по неотменённым записям;
- средний чек = сумма / число неотменённых записей.

Отменённые приёмы показываются серым, но в денежные итоги не входят —
иначе отчёт завышал бы выручку. Стоимость складывается из основной и всех
дополнительных услуг, поэтому запись на две услуги учитывается полностью.

## 3. Экспорт в Excel

Используется библиотека **EPPlus 4.5.3.3** — последняя бесплатная версия
(лицензия LGPL для учебных проектов, без коммерческого использования).
Книга создаётся в формате `.xlsx` без установленного Microsoft Excel.

Структура листа «Записи за период»:

| Строка | Содержимое |
|--------|------------|
| 1 | заголовок «Отчёт «Записи за период»», объединённые ячейки A1:G1, шрифт 16 пт |
| 2 | период, врач, признак «Только завершённые» |
| 3 | дата и время формирования (выровнено вправо) |
| 5 | заголовки таблицы: дата, время, пациент, врач, услуга, статус, стоимость |
| 6 … | строки отчёта; отменённые выделены серым |
| последняя | «Итого записей: N» и сумма без отменённых приёмов |

Оформление:

- тёмно-синяя шапка с белым текстом, рамки по периметру таблицы;
- формат чисел `#,##0.00`;
- ширины столбцов подобраны под содержимое;
- закреплена строка заголовков (`FreezePanes`);
- включён автофильтр;
- параметры печати листа: альбомная ориентация, вписывание по ширине в одну страницу.

Экспорт вызывается из `ReportsView` через `SaveFileDialog`. Имя файла
формируется автоматически: `Записи_за_период_дд.ММ.гггг_дд.ММ.гггг.xlsx`.
После сохранения пользователь может сразу открыть файл. Ошибки (например,
файл занят Excel) перехватываются и показываются по-русски.

## 4. Печать отчёта

Печатная форма реализована без сторонних компонентов — средствами
`System.Drawing.Printing`:

- класс `PeriodReportDocument` наследует `PrintDocument`;
- страница A4 альбомной ориентации, поля 40/30/40/40 (сотые дюйма);
- шапка: название клиники, название отчёта, период, врач, дата формирования;
- таблица с чередованием фона строк;
- итоговая строка с количеством записей и суммой без отменённых;
- нижний колонтитул: название системы и номер страницы;
- длинная таблица автоматически переносится на следующие страницы,
  заголовок повторяется на каждой странице.

`ReportPrinter.ShowPreview` открывает стандартное окно `PrintPreviewDialog`
с масштабированием и кнопкой печати. Ширины столбцов заданы весами
(9/7/25/24/20/8/7 %), поэтому таблица всегда помещается по ширине листа.

## 5. Диаграмма статистики

На экран статистики добавлен столбчатый график **ScottPlot.WinForms 4.1.74**
(пакет содержит сборку под .NET Framework 4.7.2). Экран разделён
`SplitContainer`: слева таблица по дням, справа диаграмма.

Алгоритм построения:

1. Из результата статистики берутся только дни с записями.
2. Дата превращается в номер дня от начала периода (ось X).
3. Строятся столбцы (`AddBar`), цвет — фирменный тёмно-синий.
4. Подписываются не более 10 дат, иначе подписи накладываются.
5. Ось Y начинается с нуля, верхняя граница — максимум + 1.
6. Если записей нет, выводится надпись «За выбранный период записей нет».

Ошибка построения графика только записывается в журнал и не прерывает
расчёт статистики: таблица и карточки остаются доступными.

## 6. Курсы валют

Раздел доступен по кнопке **«Курсы валют»** на вкладке отчётов.

**Источник данных:** открытый сервис `https://www.cbr-xml-daily.ru/daily_json.js`
(официальные курсы Центрального банка РФ в формате JSON). Адрес и таймаут
(15 секунд) вынесены в `appsettings.json`:

```json
"Currency": {
  "Url": "https://www.cbr-xml-daily.ru/daily_json.js",
  "TimeoutSeconds": 15
}
```

**Загрузка.** `CurrencyService.LoadAsync`:

1. включает TLS 1.2 (на Windows 7 он может быть выключен по умолчанию);
2. выполняет асинхронный GET, поэтому окно не «замирает»;
3. учитывает кодировку из заголовка `Content-Type` (UTF-8 либо windows-1251);
4. разбирает JSON через Newtonsoft.Json;
5. сортирует валюты по коду.

**Расчёт показателей.** ЦБ задаёт курс за номинал (1, 10, 100 единиц),
поэтому в модели `CurrencyRate` хранятся `Nominal`, `Value`, `Previous`, а также:

- `Rate = Value / Nominal` — курс за одну единицу;
- `Change = Value − Previous` — изменение в рублях;
- `ChangePercent = (Value − Previous) / Previous × 100`.

Рост курса выделяется зелёным, падение — красным. При отсутствии интернета
или таймауте показывается сообщение с просьбой проверить подключение;
приложение продолжает работать.

**Найденный дефект.** При первом запуске курсы отображались как 905 вместо 90,5.
Причина: `JToken.ToString()` форматирует число по текущей культуре, а разбор
шёл с `InvariantCulture`; в русской культуре `90.5` превращалось в `"90,5"`,
где запятая трактовалась как разделитель тысяч. Исправление — чтение числа
через `token.Value<decimal>()`, не зависящее от региональных настроек.
Добавлен регрессионный тест `Parse_WorksWithRussianCulture`.

## 7. Управление пользователями

Ранее вкладка была заглушкой. Теперь администратор может:

- просматривать список логинов и ролей, искать по логину или роли;
- добавлять пользователя (логин, роль, пароль с повтором);
- менять логин и роль;
- задавать новый пароль (пустые поля — пароль не меняется);
- удалять пользователя с подтверждением.

Ограничения:

- нельзя удалить учётную запись, под которой идёт работа;
- нельзя удалить последнего администратора или снять с него роль;
- свою роль изменить нельзя (поле заблокировано);
- логин уникален и проверяется репозиторием;
- пароль хранится только как хэш SHA256.

## 10. Доработки после этапа 3

По итогам проверки интерфейса и сценариев работы добавлены улучшения,
не меняющие общую архитектуру.

### 10.1. Учёт длительности услуг

Раньше проверялась только точка начала приёма: запись на 09:00 считалась
занятой для другой записи на 09:00, но не мешала записи на 09:15. Теперь
интервал считается по сумме длительностей основной и всех дополнительных
услуг.

Добавлен класс `Services/TimeRange.cs`:

- `TryParseMinutes` / `ParseMinutes` — строгий разбор `ЧЧ:мм`;
- `Format` — обратное форматирование;
- `Overlaps` — пересечение двух интервалов (касание границ не считается
  пересечением).

В `AppointmentRepository`:

- `GetTotalDurationMinutes` суммирует длительности услуг записи;
- `EnsureTimeRangeFree` запрещает пересечение и приём, заканчивающийся
  после 20:00;
- `CountOverlaps` сравнивает интервалы одним SQL-запросом, учитывая
  дополнительные услуги через подзапрос;
- `IsTimeRangeBusy` используется формой записи для предварительной проверки.

В форме записи показывается реальный интервал, например `09:00–10:00`,
а при выходе за 20:00 текст становится красным. При попытке сохранить
пересекающуюся запись выводится сообщение с конкретными временами.

### 10.2. Резервное копирование

В `Data/Database.cs` добавлен метод `BackupTo`. Он использует штатный
SQLite Backup API (`SqliteConnection.BackupDatabase`), поэтому копия
корректна даже при работающей программе. Старый файл назначения удаляется,
копирование поверх рабочей базы запрещено. Команда доступна в меню
**«Файл» → «Резервная копия базы…»** и по **Ctrl+B**; факт копирования
записывается в журнал.

### 10.3. Интуитивный интерфейс

- Карточки-счётчики на главной стали кнопками: щелчок открывает нужный раздел.
- Карточка «Записей сегодня» открывает журнал с включённым фильтром
  «Только сегодня» (метод `AppointmentsView.ShowToday`).
- У кнопок и карточек появились всплывающие подсказки.
- В строке состояния выводится подсказка для текущего раздела.
- Добавлены горячие клавиши `Ctrl+1…6`, `Ctrl+N`, `Ctrl+B`, `F1`.
- Если фильтры не нашли записей, вместо пустой таблицы показывается
  поясняющий текст.
- Добавлена форма `HelpForm` — краткая инструкция, горячие клавиши
  и кнопка открытия полного руководства.

### 10.4. Пакет поставки

Скрипт `scripts/Publish-Release.ps1`:

1. собирает конфигурацию Release;
2. копирует программу, библиотеки, настройки, `README.md` и папку `docs`

Рабочие папки `Data` и `Logs`, а также отладочные файлы `*.pdb` в пакет
не попадают: база и журнал создаются при первом запуске.

- сборки Debug и Release проходят без ошибок и предупреждений;
- готовый ZIP-пакет позволяет передать программу без ручной сборки папки.

Выявленный дефект с культурой чисел показал, что внешние данные нужно
разбирать независимо от региональных настроек компьютера, а не полагаться
на текущую культуру. Для подобных мест добавлены регрессионные тесты.

**Ограничения учебного проекта:** пароли хэшируются SHA256 без соли;
курсы валют требуют интернета; для просмотра Excel нужна совместимая программа;
одновременная работа нескольких пользователей с одним файлом базы не
предусмотрена. Резервная копия защищает от потери файла, но не заменяет
полноценное серверное резервирование.
